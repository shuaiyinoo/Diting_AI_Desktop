# v5.0.31

## 新功能

### 模型配置统一管理

- **语音模型配置**：将 FunASR 语音识别模型的下载、选择和管理统一提取到设置页面，用户可在「设置 → 语音模型配置」中完成全部操作，不再需要在多个入口分别配置
- **OCR 模型配置**：在设置中新增「OCR模型配置」面板，支持下载和管理 PaddlePaddle PP-OCR 全系列本地 OCR 模型，与语音模型管理体验一致
- **向量模型配置**：在设置中新增「向量模型配置」面板，支持下载、选择和管理本地向量嵌入模型，内置 Fast / Balanced / Quality 三档预设模型，覆盖不同性能与精度需求

### 模型调用链路优化

- **统一调用入口**：语音、OCR、向量三个模型配置全部收归设置中心，应用各模块（RAG 向量化、票据 OCR、语音转写等）通过统一的配置读取链路获取用户选择的模型，消除了散落在各处的硬编码模型路径
- **模型加载与验证**：向量模型选择时增加预热验证机制——用户点击确认后先做一次推理验证，确保模型文件完整可用后再写入配置并触发后续向量化，避免选择不可用模型导致队列全部失败
- **下载兜底策略**：向量模型下载支持自动判断网络环境，直连 HuggingFace 失败时自动切换国内镜像（hf-mirror.com）兜底下载，无需用户手动选择下载源
- **自定义模型管理**：向量模型支持通过 HuggingFace URL 下载自定义 ONNX 模型，模型元数据持久化到磁盘，应用重启后自动恢复模型列表
- **数据一致性保障**：切换向量模型时自动清空旧向量索引和关键词索引，重置文件状态为待处理，防止不同维度向量混用

### OCR 模型管理详情

- **全系列模型预设**：覆盖 PP-OCRv3~v6 全系列共 24 个模型预设，包括 V6 Tiny/Small/Medium、V5 多语言/英语/阿拉伯语/韩语/泰语等、V4 Mobile/Server/Doc、V3 多语言/日语，前端按系列分组展示
- **模型存储路径**：OCR 模型统一存储到 `~/.diting/model/ocr/` 目录，不再依赖库硬编码的缓存路径
- **票据 OCR 改造**：`InvoiceOcrService` 改为从本地模型路径加载，用户需先在设置中下载并选择 OCR 模型；未选择时自动回退到库默认模型
- **RAG OCR 改造**：`OcrWorkerManager` 子进程通过环境变量注入模型路径，支持在 RAG 文档解析中使用用户选择的 OCR 模型
