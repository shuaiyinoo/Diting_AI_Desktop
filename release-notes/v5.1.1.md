# Diting AI Desktop v5.1.1 更新

> 本次更新为修复版本，解决 Windows 平台远程控制功能启动时主进程崩溃的问题。

---

## 🐛 Bug 修复

### 🔧 Windows 平台远程控制崩溃修复

- **问题现象** — Windows 10 用户安装 v5.1.0 后，启动时主进程弹出 JavaScript 错误：`node-enigo\index.js:37:9 — The value of targetStart is out of range`，导致应用崩溃或远程控制功能不可用。
- **根因分析** — 旧依赖 `node-enigo@1.3.0` 虽然底层 Rust enigo 库支持 Windows，但发布到 npm 的包存在文档与产物不一致的问题：`index.js` 的平台检测函数缺少 `win32` 分支，CI 流水线从未构建 Windows 预编译二进制，npm 包内仅包含 macOS ARM64 的 `.node` 文件。Electron 在 Windows 上加载该模块时，触发 Node.js 底层 `Buffer.copy()` 越界错误，最终在 `index.js:37` 行被 catch 块重新抛出，使主进程崩溃。
- **修复方案** — 将输入模拟依赖从 `node-enigo@1.3.0` 替换为 `@touchifyapp/enigo@0.1.2`。该包基于 `@napi-rs` 架构，通过 `optionalDependencies` 为每个平台/架构发布独立的预编译子包（`@touchifyapp/enigo-win32-x64-msvc`、`@touchifyapp/enigo-darwin-arm64` 等），npm install 时自动按当前平台安装对应子包，无需 `electron-rebuild` 或 Rust 工具链。

### 输入驱动适配

- **API 迁移** — `@touchifyapp/enigo` 采用类实例 + 同步方法的设计范式（`Enigo.create()` → 实例方法），与旧包的模块级异步函数不同。`InputDriver` 抽象层已完成适配，通过 `async` 包裹同步调用，上游 `command-executor.ts` 和 `remote.ts` 零改动。
- **滚轮改进** — 旧包通过 `mouseButton('scrollDown', 'click')` 逐格模拟滚轮，新包提供原生 `scrollVertical` / `scrollHorizontal` 方法，语义更清晰。
- **类型声明** — 删除手写的 `node-enigo.d.ts`，`@touchifyapp/enigo` 自带 `index.d.ts` 类型声明。
