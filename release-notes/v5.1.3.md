# Diting AI Desktop v5.1.3 更新

> 本次更新修复了 macOS 代码签名与公证配置，启用 Hardened Runtime 并完成 Apple notarization 流程。

---

## 🐛 Bug 修复

### macOS 签名公证失败

- **问题** — 配置签名后，公证（notarization）失败，所有可执行文件报错 `The executable does not have the hardened runtime enabled`。
- **根因** — `builder-mac.json` 和 `builder-mac-arm64.json` 中 `hardenedRuntime` 显式设为 `false`，导致签名时未启用 Hardened Runtime，Apple 公证拒绝通过。
- **修复** — 将 `hardenedRuntime` 改为 `true`，新增 `entitlements.mac.plist` 权限文件声明 native 模块所需的 entitlements（JIT、动态库加载、Apple Events 等），新增 `afterSign` 钩子脚本 `build/notarize.js` 执行 notarytool 公证。

---

## 🔧 工程改动

### 构建配置

- `cmd/builder-mac.json` 和 `cmd/builder-mac-arm64.json` 新增 `hardenedRuntime`、`gatekeeperAssess`、`entitlements`、`entitlementsInherit`、`afterSign` 配置项。
- 新增 `build/entitlements.mac.plist` — Hardened Runtime 权限声明，涵盖 native 模块加载（better-sqlite3、canvas、node-pty）、JIT、Apple Events、网络访问等。
- 新增 `build/notarize.js` — afterSign 钩子脚本，使用 `@electron/notarize` 提交 notarytool 公证，未配置凭证时自动跳过。
